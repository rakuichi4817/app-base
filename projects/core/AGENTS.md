# Pythonの作業指示

- Ruffで整形・Lint、tyで型チェック、pytestでテストする。別の競合ツールを追加しない。
- 公開APIには型注釈と日本語のGoogle Style docstringを書く。該当する `Args`・`Returns`・`Raises` を実装と一致させる。
- ロジックのまとまりの間に空行を入れる。
- 絶対時刻はタイムゾーン付きUTCを使い、async経路で長時間の同期I/Oを直接実行しない。docstringはgeneratorのYieldsや契約上の例外も実装と照合する。
- FastAPI・HTTP・フロントエンドへ依存させない。
- ドメインモデル（`domain`）は状態・不変条件、ドメインサービス（`domain_service`）は単一モデルに置けない業務ルールや外部サービスを使う業務機能、リポジトリ（`repository`）は保存・取得を担当する。
- DB・SDKの具体実装も責務別に置き、インフラストラクチャー（`infrastructure`）へ一律集約しない。ユースケースの調整・トランザクション・クライアントのライフサイクルは各利用側に置く。
- テストは正常・異常・境界の異なる振る舞いに絞り、時刻・乱数・sleepに依存させない。
- テスト名は `test_条件と期待結果` の日本語とする。純粋な業務処理は実物で、リポジトリ（`repository`）の保存・制約・トランザクションはテスト用DBや公式エミュレーターで検証し、その保証をモックしない。
- 外部SDKの正常動作を模倣する独自fakeで接続検証を代用しない。モックの回数・引数は呼び出し方自体が要件の場合だけassertする。
