単独化するときはルートmiseのconfig_roots・集約タスク・lock:refresh、workspaceのフォルダーと推奨拡張、Dependabotの対象、CI・Dockerの参照を必ず整理します。単一プロジェクトならmonorepo_root・monorepo設定を外し、必要なtoolsと子タスクを新しいルートへ統合します。
## 一式コピーの共通手順

1. `.venv`・`node_modules`・ビルド出力を除いてコピーする。
2. READMEの名前・説明、ワークスペースのファイル名を変更する。
3. `app-base-core` / `app-base-backend` / `app-base-frontend` とimport名を変更する。Pythonは `src/` のディレクトリ名・import・backendの `[tool.uv.sources]`・uvicorn起動先も揃える。
4. コピー先で `mise trust --all`、`mise install` を実行する。
5. `mise run lock:refresh` で名前変更をロックへ反映し、`mise run install`、`mise run check` を実行する。
6. 挨拶サンプルを必要な機能へ置き換える。
7. AGENTS・ドキュメント・CIのブランチ名を用途に合わせる。

Git管理を始める場合は初期化前に `.gitignore` と含めるファイルを確認してください。GitHubでの公開範囲・ライセンス・元資料の再利用可否は別途確認が必要です。

## 部分的に参考にする

| 必要なもの | 主な参照先 | 一緒に確認するもの |
| --- | --- | --- |
| miseとモノレポ | ルート・子の `mise.toml` | `config_roots`、集約タスク、子設定の信頼 |
| Python標準構成 | coreの `pyproject.toml`・mise・src・tests | Python版、ロック、uv_buildの命名規則 |
| FastAPI | backend | coreへのローカル依存が不要なら削除 |
| ty・RuffとVS Code | workspace、各 `.vscode/settings.json` | `.venv`、推奨拡張、ty/Ruffの開発依存 |
| Vue / TS | frontend | Node/pnpm版、Vite、tsconfig、vue-tsc |
| Tailwindと整形 | CSS、Vite、ESLint、Prettier設定 | CSSエントリー指定、プラグイン依存 |
| 基本CI | `.github/workflows/ci.yml` | miseタスク、ロック、ブランチ名 |

coreを削除するなら、backendの依存・import・サンプルAPIと、ルートmise・workspace・Dependabotの参照も合わせて整理してください。

## Python単独

完成形は `pyproject.toml`・uv.lock・src・tests・mise.toml・.vscodeを持つ1プロジェクトです。

1. `projects/core/` を新しいルートへコピーする。.venv・キャッシュはコピーしない。
2. 子のmise.tomlに元ルートのtoolsからpython・uvだけを移す。Node・pnpm・モノレポ設定は不要。
3. 配布名app-base-core、import名app_base_core、srcのディレクトリとテストのimportを同時に変更する。
4. coreの.vscodeを使い、元workspaceのty・Ruff共通設定と推奨拡張のPython・mise・TOMLだけを新しいworkspaceへ取り込む。既存のインタープリター選択も確認する。
5. `mise trust` → `mise install` → `mise exec -- uv lock` → `mise run install` → `mise run lint` → `mise run test`。

CIは新ルートのmise run install/lint/testだけを呼びます。Dependabotのuv対象は `/` にし、npm・Docker・frontendへの参照を持ち込みません。
ライセンス検査はコピーしたmiseのlicenseタスクをそのまま使い、`--ignore-packages` の自作パッケージ名を改名後の名前に合わせます。許可表記は転用先で見直してください。[Python](Python.md)・[設計・実装方針](設計・実装方針.md)・[テスト方針](テスト方針.md)と必要なAGENTS規則も引き継ぎます。licenseグループのpip-licensesは本番依存ではありません。

## FastAPI単独

backendをAPI専用で使います。coreを残すなら元の相対配置を維持し、ルートmiseからfrontendのtools・config_roots・タスク参照を外します。
coreが不要ならbackendを新しいルートへコピーし、pyprojectのapp-base-core依存とtool.uv.sources、mainのcore import・挨拶サンプルと対応テストを外し、必要なAPIへ置き換えます。
子miseにpython・uvのtoolsを移し、uvicornのimportパスを変更後の名前へ揃えます。静的配信が不要ならSTATIC_DIRを設定せず、必要なら静的配信コードとテストも外します。

`mise trust` → `mise install` → `mise exec -- uv lock` → `mise run install` → `mise run lint` → `mise run test` → `mise run dev` で `/docs` を確認します。
VS Codeは各Python環境を指定し、CIとDependabotのuv対象を移動後のパスへ変更します。元のDockerfileはVueビルド前提なのでそのまま使わず、Pythonのビルド・実行ステージだけに変更してください。
APIの[公開エラー契約](設計・実装方針.md#エラー処理)を引き継ぎ、公開してよい理由と内部例外を分けます。

## TypeScript単独

frontend全体ではなく設定を起点にします。Vue依存を削る途中で元サンプルを残さないよう、新しいsrcとテストを用意してください。

1. package.json・pnpm設定・Prettier・ESLint・miseを取り出し、元ルートからnode・pnpmのtoolsを移す。
2. vue・reka-ui・vue-query・plugin-vue・vue-tsc・vue-test-utils・StorybookのVue関連・Tailwind関連を外す。ESLintのVueパーサーとTailwind設定、PrettierのTailwindプラグインとCSS参照も外す。
3. 型検証を `tsc --noEmit` に変更し、Vueのtsconfig参照を廃止する。Vitest設定からVueプラグインを外す。

### Node.js用

typesはnode、libはES2023などDOMなし、ESLint globalsはnodeに限定します。Nodeで直接動かす配布JSを作るならmodule/moduleResolutionはNodeNext、outDirはdist、noEmitをfalseにし、package.jsonのtypeとimport拡張子を合わせます。Vitestはnode環境。Vite・index.html・jsdomは不要です。

### ブラウザー用

libにDOM・DOM.Iterable、moduleResolutionにBundler、ESLint globalsにbrowserを指定します。Viteを使うならVue/Tailwindプラグインなしの設定とindex.htmlを用意します。tscだけではバンドルやブラウザー配信をしません。DOMを検証するケースだけjsdomを使います。

### 共通の確認

`mise trust` → `mise install` → `mise exec -- pnpm install`（新しいロックを生成）→ `mise run lint` → `mise run test`。ビルドが必要なら対応タスクを作って実行します。
VS CodeからPython・Vue・Tailwindの不要拡張を外し、CIは新しいmiseタスクだけ、Dependabotはnpmの新ルートを指定します。ライセンス検査はfrontendのlicenseタスクを引き継ぎ、許可表記を転用先で見直します。Pythonへの参照は不要です。

## Vue単独

frontendを新しいルートへコピーし、node_modules・dist・storybook-staticは除外します。子miseに元ルートのnode・pnpm toolsを移し、package名を変更します。
backendがないため、Viteの/apiプロキシを接続先へ変更するか削除し、APIクライアントと挨拶サンプルを用途に合わせます。接続先とCORSはサーバー側も合わせて設計してください。

`mise trust` → `mise install` → `mise exec -- pnpm install` → `mise run lint` → `mise run test` → `mise run build` → `mise run dev`。
Storybookを残すなら[ブラウザー導入](TypeScript・Vue.md#storybook)後に `mise run storybook:test` と `mise run storybook:build` を確認します。不要なら.storybook・Story・vitest.storybook.config、関連依存・scripts・miseタスク・CI手順をセットで外します。
VS CodeはVue・ESLint・Prettier・Tailwind・miseを引き継ぎ、Python環境指定を外します。Dependabotはnpmの `/`、CIもfrontend専用のタスクへ変更します。配布はdistを静的ホストへ配置し、画面ルーターを追加するならホスト側のSPAフォールバックを設定します。

## Python＋Vue＋Docker一式

[共通手順](#一式コピーの共通手順)でコピー・改名・ロック更新を行います。coreを含む相対配置を保ち、DockerfileのCOPY・uvicorn起動先とcomposeのname/image、ワークスペース名も変更します。

`mise run install` → `mise run check` → `mise run license` → ブラウザー導入 → `mise run storybook:test` → `mise run storybook:build` → `mise run docker:up` の順で確認します。
Dockerの画面・API・SPAの404を確認し `mise run docker:down` で終了します。通常開発はmise run devです。
CIのブランチ名・必須チェック、Dependabotの対象、OSSの配布義務を転用先で確認します。GitHub公開・自作コードのライセンス・クラウドへの配備は自動化していません。

## 既存プロジェクトへ設定だけ導入

既存のpyproject・package.json・VS Code設定・ロック・CIを丸ごと上書きしません。

1. 既存ツール・規則と競合を確認し、miseのtoolsとタスクを必要分だけ統合する。
2. PythonならRuff・ty・pytestの開発依存と設定を移す。Black/isort等を置き換えるか共存を避ける方針を決める。
3. TSならESLint flat config・Prettier・tsconfigを統合し、Vue/Tailwindがない環境へ対応プラグインを持ち込まない。
4. 保存時整形とCIが同じツールを使うようにし、既存のロック更新手順で依存を再解決する。
5. 対象のLint・型・テストを実行してからCIへ接続する。全体整形は業務変更と分け、意図しない差分を確認する。

Storybook・エラー契約・ライセンス検査は独立して導入できますが、既存のAPI利用者や配布ルールを無断で変えません。AGENTSは既存指示へ必要な規則だけ統合してください。

## 意図的に含めていないもの

認証・DB・マイグレーション・クラウド・監視・全体E2E・配備先へのデプロイは含めていません。Storybookとライセンス一次検査は含みますが、配布義務の確認は別途必要です。

Dockerの単一コンテナー配信は [Dockerガイド](Docker.md) を参照してください。不要なら `projects/app/.docker/`・`.dockerignore`・`compose.yml` とルートmiseの `docker:*` タスクを除外できます。
